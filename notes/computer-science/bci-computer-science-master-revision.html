Decimal Fraction → Binary (e.g. 26.85)

Integer part: repeated ÷2, read remainders bottom→top: 26 → 11010

Fraction part: repeated ×2, take integer digit each time: 0.85 → 110110 (approx)

Memory Chip — Address Lines Numerical (Hindi Note) ⭐⭐⭐⭐⭐

Memory Chip में तीन तरह की Lines होती हैं: Address Lines (Location चुनती हैं), Data Lines (Data भेजती हैं), Control Lines (CS, RD, WR)।

दो अलग तरह के Question पहचानो:

Question में क्या दिया हैFormula
Memory Organization (जैसे 4M×8, 1M×16)Address Lines = log₂(Total Words)
Total External Connections (Pins)Address Lines = Total Connections − Data Lines − Control/Power Lines

उदाहरण (Type-1): 4M-bit Chip, Data Lines = 8 → कुल Bits = 4×2²⁰ = 2²² → Words = 2²²÷2³ = 2¹⁹ → Address Lines = 19

उदाहरण (Type-2): External Connections = 19, Data Lines = 8, Control/Power = 2 (आमतौर पर) → Address Lines = 19−8−2 = 9

🧠 Question में "Organization/Words" दिखे → 2ⁿ Rule लगाओ; "External Connections/Pins" दिखे → Total−Data−Control लगाओ

❌ ट्रैप: दोनों तरह के Question में अलग Formula चाहिए — Language ध्यान से पढ़ो, वरना जवाब उल्टा आएगा।

🗂️ Cache Memory — Direct Mapping Numerical ▼

⭐⭐⭐⭐⭐ CPU का दिया 32-bit Address तीन हिस्सों में टूटता है:

| Tag | Index | Offset |
FieldकामFormula
OffsetBlock के अंदर कौन-सा Byte चाहिएlog₂(Block Size)
IndexCache की कौन-सी Line देखनी हैlog₂(Cache Size ÷ Block Size)
Tagपहचान — उस Line में असल में RAM का कौन-सा Block रखा हैTotal Address Bits − Index − Offset

उदाहरण: 32-bit Address, 32 KB Direct Mapped Cache, Block Size = 32 Bytes

  • Offset = log₂(32) = 5
  • Cache Lines = 32KB ÷ 32B = 32768÷32 = 1024 = 2¹⁰ → Index = 10
  • Tag = 32 − 10 − 5 = 17

✅ Answer: Index = 10, Tag = 17

🧠 Tag=Identity(कौन-सा Block), Index=Location(कौन-सी Line), Offset=Byte(Block के अंदर)

Block Size दुगुना → Offset +1 बढ़ेगा। Cache Size दुगुना → Index +1 बढ़ेगा। Address Size बढ़े → Tag बढ़ेगा।

Process Synchronization — Critical Section (Hindi Note) ⭐⭐⭐⭐⭐

Critical Section वह Code का हिस्सा है जहाँ दो या ज़्यादा Process एक ही Shared Resource (जैसे Database Record) को Access/Change करती हैं। साथ में घुसने से Data खराब हो जाता है, इसे Race Condition कहते हैं।

Critical Section Problem को पूरी तरह हल करने के लिए न्यूनतम 2 Shared Variables चाहिए — यही Peterson's Algorithm Use करता है:

  • flag[2] (Boolean Array) — बताता है कौन-सी Process अंदर जाने के लिए तैयार है
  • turn (Integer) — तय करता है अभी किसकी बारी है

❌ सिर्फ 1 Variable (जैसे सिर्फ turn) से काम नहीं चलता — Progress की शर्त टूट जाती है।

Critical Section Solution की 3 ज़रूरी शर्तें:

  1. Mutual Exclusion — एक बार में सिर्फ एक Process अंदर
  2. Progress — खाली बैठी Process दूसरी इच्छुक Process को रोके नहीं
  3. Bounded Waiting — अनंत काल तक इंतज़ार न हो
🧠 Critical Section हल करने के लिए Minimum 2 Variables (flag + turn) चाहिए — Peterson's Algorithm

FCFS Disk Scheduling (Hindi Note)

Head जितने क्रम में Requests आती हैं, उतने ही क्रम में Service होती है। Total Head Movement = हर Step पर |Current − Next| का Absolute Difference जोड़ते जाओ।

उदाहरण: Requests क्रम 40(शुरुआत)→90→150→50→140→30→20 हो तो Movement: 50+60+100+90+110+10 = 420

🧠 FCFS Disk Scheduling = सभी Absolute Distances (|Current−Next|) जोड़ो

OSI Application Layer — क्या करता है

User और Network के बीच Direct Interface — मुख्य काम User को Network Services देना। इसमें आते हैं: NVT (Network Virtual Terminal — Remote Login, जैसे Telnet) और FTAM (File Transfer Access and Management — File Access/Transfer)।

❌ ट्रैप: Data Compression/Encryption = Presentation Layer का काम (Application का नहीं); Segments बनाना = Transport Layer; Dialog/Synchronization = Session Layer। Application Layer Protocols: HTTP, FTP, SMTP, DNS, DHCP, Telnet, POP3।

🔗 Network Topologies (Mesh / Star / Ring) ▼

Mesh Topology

Every node has a dedicated point-to-point link to every other node → maximum fault tolerance (if one link fails, alternate paths exist).

🧠 Links = n(n−1)/2 — NOT n(n+1)/2. Ports per node = n−1.

Example: 4 nodes → Links = 4×3/2 = 6.

❌ Common trap: "Mesh is cheapest/easiest for hundreds of computers" — FALSE. For 100 nodes, links = 100×99/2 = 4950 → extremely expensive/impractical. Mesh is used where reliability matters most (military, banking, data centers, backbone, wireless mesh), not for cost-saving.

Star Topology

  • All devices connect to a central Hub/Switch
  • Single cable failure → only that one device disconnects, rest of network keeps working
  • Central Hub/Switch failure → entire network goes down
  • Easiest to add/remove a device (just one cable)
  • Modern Switch is an active device (regenerates signal) — not passive
  • Each workstation needs only 1 NIC port (not n−1)
🧠 Star: Cable fail = 1 node down. Hub/Switch fail = whole network down.

Ring Topology

  • Each device connects to exactly 2 neighbours
  • Signal travels in one direction (classic Ring); dual-direction only in Dual Ring variants like FDDI
  • Every device acts as a Repeater (regenerates signal)
  • Uses Token Passing → no collisions (only the device holding the Token can transmit)

❌ Trap: "Ring is always more efficient than Star because data flows both directions" — FALSE for classic Ring (one direction); also modern switch-based Star often outperforms Ring anyway.

📡 Transmission Media (UTP / Coax / Fiber / Infrared) ▼

UTP (Unshielded Twisted Pair)

  • No shielding; twisting of wire pairs cancels out EMI noise (Cancellation Effect)
  • 568B: Pins 1-2 = Transmit, Pins 3-6 = Receive
  • Max length = 100 m (90 m permanent cable + 10 m patch cable)
  • Cat6 reduces crosstalk via more twisting / better construction — NOT via higher voltage (common trap)

Coaxial Cable

  • Structure: Copper Core → Dielectric → Shield → Outer Jacket
  • Has a shield → less EMI-prone than UTP (opposite of a common trap statement)
  • Characteristic Impedance depends on inner/outer diameter + dielectric material — NOT on cable length
  • Skin Effect: at high frequency, current flows mainly on the conductor's surface, increasing effective resistance
  • Terminator (50Ω or 75Ω) required in Bus topology to prevent signal reflection
CableStandardUse
RG-810Base5Thick Ethernet (Thicknet)
RG-5810Base2Thin Ethernet (Thinnet)
RG-59—TV / CCTV (not gigabit backbone)

Optical Fiber — Attenuation causes (trick: ABS)

  • Absorption — light energy absorbed, converted to heat
  • Bending loss — excess bending lets light escape
  • Scattering — micro-defects scatter light

Fiber has the lowest attenuation among media, not zero attenuation, and attenuation does NOT increase bandwidth.

Infrared

  • Requires Line-of-Sight; cannot pass through walls/opaque objects
  • Confined to one room → naturally more secure (signal can't be intercepted from outside)
  • Not related to Ground Wave (that's for low-frequency radio)

IPSec — IP Security Protocol

Network Layer पर काम करने वाला Protocol Suite जो IP Traffic को Authentication + Integrity + Encryption तीनों देता है — मुख्यतः VPN में उपयोग होता है। दो Modes: Transport Mode (सिर्फ Payload Encrypt) और Tunnel Mode (पूरा IP Packet Encrypt, नया Header — VPN में यही use होता है)। दो Sub-protocols: AH (Authentication Header — सिर्फ Integrity/Auth) और ESP (Encapsulating Security Payload — Encryption भी देता है)।

🧠 IPSec = IP + Security (नाम में ही जवाब); ARP/ICMP/DHCP कोई Security नहीं देते

Port Security (Managed Switch)

Switch के किसी Port पर जुड़ने वाले Devices के MAC Address की संख्या/पहचान Limit करने वाला Layer-2 Security Feature। Unauthorized MAC जुड़ते ही Violation Action होता है — Protect (Drop), Restrict (Drop+Alert), या Shutdown (Port बंद — Default)।

🧠 Port Security = Switch Port पर MAC Address Lock (VLAN Trunking अलग चीज़ है — वह Traffic Route करता है, Security नहीं)

Physical Security — Mantrap

दो Interlocking Doors वाला छोटा Room — दोनों Doors कभी एक साथ नहीं खुलते; पहला Door बंद होने और Identity Verify होने के बाद ही दूसरा खुलता है। उद्देश्य: Tailgating/Piggybacking और Unauthorized Entry रोकना (Data Center जैसी जगहों पर)।

🧠 Mantrap = Man को Trap करने वाला Room, 2 Doors कभी साथ नहीं खुलते

Wi-Fi Security — SSID Hiding vs WPA3/OWE

  • SSID Hiding: Router SSID Broadcast बंद कर देता है, Network List में नहीं दिखता — लेकिन यह Security Feature नहीं है (Management Packets से फिर भी पता चल सकता है)। ❌ ट्रैप: "SSID Hiding Professional Hackers से Complete Security देता है" — गलत, यह सिर्फ Visibility कम करता है
  • WPA2 Open: कोई Encryption नहीं — कोई भी Traffic Sniff कर सकता है
  • WPA3 Open: OWE (Opportunistic Wireless Encryption) Use करता है — Password नहीं आता (Network फिर भी Open रहता है) लेकिन हर User का Traffic अलग-अलग Encrypt होता है, इससे Passive Eavesdropping रुकती है
🧠 SSID Hidden ≠ SSID Secure; WPA2 Open=No Encryption, WPA3 Open=OWE Encryption (पर फिर भी Password-less)

Function Overloading — Compiler के अंदर क्या होता है

Compiler हर Overloaded Function की परिभाषा के लिए एक अलग (Separate) Function Set करता है — इस Process को Name Mangling कहते हैं (नाम के साथ Argument Types जोड़कर Unique नाम बनाना)।

  • ✅ Overloaded Functions में Arguments की संख्या समान हो सकती है — बशर्ते Data Type अलग हो: void display(int,int) और void display(float,float) दोनों Valid हैं
  • ❌ ट्रैप: "Overloaded Functions में Arguments की संख्या कभी समान नहीं हो सकती" — यह गलत Statement है
  • ❌ सिर्फ Return Type बदलने से Overloading नहीं होती — यह Compile Error देगा
🧠 Overloading के लिए: नाम समान, संख्या OR Type OR क्रम में से कम-से-कम एक अलग होना चाहिए; सिर्फ Return Type काफी नहीं

Class Size — Static Data Members कभी नहीं गिनते

sizeof(ClassName) निकालते समय Compiler सिर्फ Non-static (Instance) Variables का Size जोड़ता है। static Variables/Functions पूरे Program में एक बार ही एक Shared Global Area में बनते हैं — Object का हिस्सा नहीं होते, इसलिए Class Size में उनका योगदान हमेशा 0 होता है।

class Test {
    static int i;   // योगदान = 0
    int j;          // योगदान = 4 bytes
};
// sizeof(Test) = 4

अगर Class में सिर्फ static Members हों (कोई Non-static नहीं), तो वह Class खाली (Empty Class) मानी जाती है और उसका Size 1 Byte होता है (Compiler हर Object को Unique Address देने के लिए 1 Byte Reserve करता है)।

🧠 Static Variable = "बाहर वाला कमरा" — Class के Size में कभी नहीं जुड़ता

Huffman Coding

⭐⭐⭐⭐⭐⭐ Greedy algorithm, uses Priority Queue (Min Heap), complexity O(n log n). Used for Lossless Compression (ZIP, PNG, MP3, PDF, text).

Steps: build leaf nodes for each symbol → put in priority queue → repeatedly combine two lowest-frequency nodes → repeat until one tree remains. Property: low frequency → long code, high frequency → short code (Prefix Code — no code is a prefix of another).

Static Array की सीमा

C/C++ में साधारण Array (जैसे arr[5]) एक बार Define होने के बाद Fixed-size होता है — Compile-time पर Memory Allocate होती है, Run-time पर अपने आप नहीं बढ़ता। Full Array में बिना Size बढ़ाए नया Element Insert करना संभव नहीं। यह सुविधा सिर्फ Dynamic Structures (C++ vector, Java ArrayList) में मिलती है।

🧠 Array = Fixed-size Static Memory; स्वतः नहीं बढ़ता (Vector/ArrayList ही Resizable हैं)

Circular Linked List — Application

Last Node का Pointer वापस First Node को Point करता है (कोई NULL नहीं) — यह एक Continuous Loop बनाता है। सबसे उपयुक्त Application: Round Robin CPU Scheduling (हर Process को बारी-बारी Time Slice मिलना, अंत के बाद वापस शुरुआत में जाना) और Music Playlist का "Repeat All"।

🧠 Circular = Continuous Loop → Round Robin Scheduling इसका Classic Example है

Circular Array — Deque में क्यों बेहतर

Linear Array में Front से Delete करने पर बाकी Elements को Shift करना पड़ता है (या जगह हमेशा के लिए बर्बाद हो जाती है)। Circular Array में (index+1) % size Formula से Front/Rear वापस शुरुआत पर घूम जाते हैं — इससे Unnecessary Shifting से बचाव होता है और Space का पूरा उपयोग होता है।

🧠 Circular Array = No Shifting + Full Space Reuse (Formula: (index+1)%capacity)

Bucket Sort — अंदर Sort क्यों जरूरी

Bucket Sort तत्वों को उनकी Range के अनुसार Buckets में बाँट देता है, लेकिन हर Bucket के अंदर तत्व अनसॉर्टेड ही रहते हैं। इसलिए हर Bucket पर अलग से (आमतौर पर Insertion Sort) चलाना पड़ता है। Steps: Buckets बनाओ → Elements Distribute करो → हर Bucket अलग से Sort करो → सबको जोड़ दो (Merge)।

🧠 Bucket Sort = Distribute (Unsorted अंदर) + Internal Sort (Insertion Sort) + Merge

🕸️ Graph Algorithms ▼

Simple Graph — परिभाषा

वह Graph जिसमें कोई Self-loop (Node से खुद पर आने वाला Edge) और कोई Multiple/Parallel Edges (दो Nodes के बीच एक से ज्यादा Edge) न हो। ऐसे Elements होने पर उसे Multigraph/Pseudo-graph कहते हैं, Simple Graph नहीं।

  • ❌ ट्रैप: "Simple Graph हमेशा Complete Graph होता है" — गलत, Simple Graph खाली (बिना Edge के) भी हो सकता है
  • Complete Graph (Kₙ): हर Node बाकी सभी से जुड़ा — Edges = n(n−1)/2 (Undirected)
  • Handshaking Lemma: सभी Nodes की Degree का योग = 2 × Edges की संख्या (Σdeg(v) = 2E)
🧠 Simple = "No Extra Extra" — No Self-loop, No Multiple Edges; हर Complete Graph Simple होता है, पर हर Simple Complete नहीं

Minimum Spanning Tree (MST)

Edges in MST = Vertices − 1. No cycles. Requires a connected graph. Algorithms: Kruskal (sorts edges, uses Union-Find) and Prim (grows from a vertex, uses Priority Queue).

Graph Theory — Degree और Tree Edges (Hindi Note)

  • ❌ ट्रैप: अगर Vertices की संख्या n है, तो Maximum Degree "n" नहीं होती — एक Vertex बाकी बचे (n−1) Vertices से ही जुड़ सकता है, इसलिए Maximum Degree = n−1
  • बिना Cycle वाले Graph (यानी Tree) में Maximum Edges = n−1
🧠 Max Degree = n−1, Tree की Edges भी = n−1

Blood Relation Puzzle — Gender Counting Trick ⭐⭐⭐⭐⭐

जब Question में "पुरुषों की संख्या = स्त्रियों की संख्या" जैसा Hint दिया हो, तो सबसे पहले जिनका Gender सीधे पता चल जाए उन्हें Count करो। जैसे ही एक Gender की Maximum संख्या पूरी हो जाए, बाकी सभी बचे सदस्य अपने-आप दूसरे Gender के मान लो। इसके बाद ही Family Tree बनाओ (Gender: + = पुरुष, − = स्त्री)।

Niece (भतीजी/भांजी) = भाई/बहन की बेटी; Nephew (भतीजा/भांजा) = भाई/बहन का बेटा।

🧠 Count First, Draw Next — पहले Gender गिनकर तय करो, फिर Tree बनाओ

Binary Operation Result — Decimal Conversion Shortcut

Binary Addition/Subtraction वाले Options में से सही Operation ढूँढने का सबसे तेज़ तरीका: पहले Target Binary Number को Decimal में बदलो, फिर हर Option के दोनों Numbers को भी Decimal में बदलकर Simple जोड़/घटाव करो जो Option Match करे वही Answer है — सीधे Binary Borrow/Carry में उलझने से बेहतर है यह Shortcut।
